## Gỡ và rollback

Boundary: `aws iam set-default-policy-version --policy-arn arn:aws:iam::138150704839:policy/mrapi-workload-boundary --version-id v2`. v2 vẫn còn, v3 giữ lại được. Sau khi về v2, export của Lambda có thể lỗi vì mất 2 action, nên tắt rule trước.

Tài nguyên SG: lệnh theo thứ tự ở [thông số Lambda](../../infra/lambda/ap-southeast-1/mrapi-exporter.md#gỡ). Role: gỡ sau Lambda, theo [README role](../../infra/iam/roles/mrapi-exporter-role/README.md). Object export có thể giữ lại.

## Phát hiện khác

- **Boundary trong repo lệch AWS.** `infra/iam/policies/mrapi-workload-boundary.json` chưa sửa, đang chờ quyết định. Giờ AWS đã ở v3 nên lệch thêm.
- `ClientToken` theo ngày chỉ chống trùng trong 8 giờ sau khi export xong (theo tài liệu AWS, chưa kiểm chứng). Export lúc 18:00 UTC cách lần invoke này hơn 8 giờ, nên dự kiến tạo export mới; nếu AWS vẫn giữ token thì lần đó trả về export cũ và không có object mới.
- Bộ nhớ 96/128 MB, còn dư nhưng không nhiều.
- Lambda code `mrapi-proxy` trên AWS thiếu 48 file ESM và type trong `@aws-sdk/core` so với local. `dist-cjs` trùng nên runtime không ảnh hưởng.
- `~/exporter` của CloudShell us-east-1 còn các file tạm, không có dữ liệu tenant, có thể xóa.
